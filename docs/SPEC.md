## 1. Что это

Настольное приложение для **macOS и Linux**, которое генерирует **бинауральные биения** —
тот самый «звук, который человек воспринимает внутри головы».

Пользователь задаёт **две независимые частоты**: одну для левого наушника, другую для правого.
Мозг сливает два тона и слышит **третий, виртуальный тон** с частотой, равной **разности** двух
исходных. Этот фантомный тон и есть бинауральное биение.

```
Левое ухо:   fL = 205.0 Гц
Правое ухо:  fR = 215.0 Гц
                    ↓
Воспринимается:    10.0 Гц   ← биение, его "слышит" только мозг
```

Формально: `beat = |fL − fR|`, средняя (несущая) = `(fL + fR) / 2`.

### 2.1 Что говорит литература (влияет на дефолты)

Изучены: систематический обзор 2023 (PMC10198548), Pratt et al. 2009 (ERP),
Reznik & Allen 2020 (eNeuro), Garcia-Argibay et al. 2025 (Sci Rep) и др.

| Факт | Откуда | Следствие для приложения |
|---|---|---|
| Биение воспринимается в диапазоне **≈1–30 Гц** — это совпадает с основными ЭЭГ-диапазонами | систематический обзор 2023 | Подсказка, если `beat` вне 0.5–100 Гц; пресеты — внутри 1–30 |
| **Низкая несущая работает лучше**: 400 Гц даёт отклик, выше 3 кГц — не обнаруживается; пик на 250 Гц | Pratt 2009, Schwarz & Taylor 2004 | Дефолтная несущая **200–400 Гц**, максимум не тащить выше 1000 Гц без предупреждения |
| Подтверждённые отклики: **FFR** на несущей и **ASSR** на частоте биения | Reznik & Allen 2020 | Показываем обе величины: несущая и разность |
| **Маскировка белым шумом ослабляет** энтрейнмент | Garcia-Argibay 2025 | Никакого шума в сигнале по умолчанию; опция шума — выключена |
| Результаты по эффектам **противоречивы**: 6 из 14 исследований поддерживают гипотезу, 9 — нет | систематический обзор 2023 | Честная формулировка в README и в справочнике, без обещаний |
| Длительность стимуляции в исследованиях: **5–15 минут** | обзор 2023 | Таймер сессии по умолчанию — 15 мин, с плавным затуханием |

Это не меняет сути приложения, но задаёт **разумные дефолты** и тон текстов.

Ключевое свойство: **на колонках эффекта нет.** Два тона смешиваются в воздухе ещё до ушей,
приходят в каждое ухо вперемешку, и мозгу не из чего вычислить разность. Поэтому наушники
обязательны — это не рекомендация, а физическое условие работы метода.

## 2. Принцип работы

```
   ┌─────────────┐      ┌─────────────┐
   │ Oscillator  │      │ Oscillator  │
   │   L: fL     │      │   R: fR     │
   └──────┬──────┘      └──────┬──────┘
          │                    │
          └────────┬───────────┘
                   ▼
            Stereo output  ──►  Левый наушник / Правый наушник
                   │
                   ▼
            Мозг слышит тон на |fL − fR|
```

Технически это два синусоидальных осциллятора с независимыми частотами и фазами,
выводимых в левый и правый канал стереовыхода. Никакой обработки, никакой сцены —
чистая генерация.

| Вопрос | Решение |

## 4. Проверка наушников при запуске

Обязательный этап. Два уровня, оба выполняются:

### 4.1 Эвристика (автоматически, без вопросов)

Собираем список устройств вывода и классифицируем:

| Признак | Вердикт |
|---|---|
| Транспорт `Bluetooth` / `BluetoothLE`, имя содержит `AirPods`, `buds`, `headset`, `Headphone` | **Наверняка наушники** ✅ |
| Транспорт `USB`, имя содержит `Headphone`, `Earphone` | **Скорее наушники** ✅ |
| Транспорт `builtin`, имя содержит `Speaker(s)`, `Динамики`, `BuiltInSpeaker` | **Колонки** ❌ |
| Транспорт `HDMI` / `DisplayPort` / `AirPlay` (монитор, ТВ) | **Колонки** ❌ |
| Транспорт `PCI`, виртуальные драйверы (BlackHole, Loopback) | **Виртуальное устройство** ⚠️ |

**macOS:** CoreAudio (`kAudioDevicePropertyTransportType`, `kAudioDevicePropertyDeviceNameCFString`,
`kAudioHardwarePropertyDefaultOutputDevice`). Реализация — маленький Swift-хелпер или `ctypes`.

**Linux:** PulseAudio/PipeWire через `pactl list sinks` / `pw-cli`, плюс ALSA jack
(`amixer get Master`, `/proc/asound/card*/`).

### 4.2 Быстрый перцептивный тест (если эвристика не дала «наверняка»)

Именно он решает вопрос окончательно, потому что показывает реальный результат, а не догадку
об оборудовании.

1. Короткий тон (≈1.5 с) жёстко **в левый** канал
2. Пауза ≈0.3 с
3. Короткий тон (≈1.5 с) жёстко **в правый** канал
4. Вопрос: **«Что вы услышали?»**
   - `Left → Right` — ✅ наушники, каналы верны
   - `Right → Left` — ✅ наушники, каналы **поменяны местами** (запоминаем, это важно!)
   - `Both at once / Can't tell apart` — ❌ колонки или моно-микшер

Если каналы перепутаны — приложение помнит это и при генерации **меняет их местами**,
иначе пользователь получит не ту разность и не ту сторону.

### 4.3 Если наушники не подтверждены

Диалог, а не блокировка:

> **Headphones recommended**
>
> Binaural beats only work when each ear receives its own tone. On speakers the two
> frequencies mix in the air before reaching your ears, and the effect disappears.
>
> [ Continue anyway ]  [ Retry check ]

`Continue anyway` — работает всё. Окно приложения при этом показывает постоянный индикатор
⚠︎ `Speakers detected` в статусной строке.

**Когда показывается диалог.** Один раз — при первом запуске и до первого подтверждения
(`Session.headphone_check_acknowledged`). Модальное окно при каждом запуске — это просто
придирание, а не забота, поэтому:

- **эвристика §4.1 выполняется на каждом запуске** — это два чтения свойств устройства, и
  пользователь мог подключить наушники со вчерашнего дня; индикатор в статусной строке
  всегда показывает текущий вердикт;
- **диалог открывается**, только если вердикт не «наушники» **и** предупреждение ещё не
  подтверждено. Подтвердил — больше не повторяем; наушники нашлись сами — повторять нечего;
- **перезапустить проверку** можно в любой момент из `Settings` и из меню *Справка*.

## 5. Функциональные требования

### F1 — Две независимые частоты ⭐ ядро
- Отдельные поля ввода и слайдеры для **левого** и **правого** канала
- Диапазон: 1–20000 Гц, шаг 0.1 Гц, точный ввод с клавиатуры
- **Независимость** — изменение левого не двигает правый (и наоборот)
- Живой расчёт и показ: `Beat: |fL − fR|` и `Carrier: (fL + fR) / 2`
- Если `beat` вне диапазона 0.5–100 Гц — подсказка, что вне типичного диапазона восприятия

### F2 — Воспроизведение
- Запуск/остановка (Space), громкость, mute
- **Без щелчков** при изменении частоты: плавный рост/убывание амплитуды (fade ≈ 20–50 мс),
  смена частоты без разрыва фазы
- Выход: стерео, float32, частота дискретизации устройства (обычно 48000)
- Кнопка стоп обнуляет каналы

### F3 — Пресеты: две ступени, реестр общий
Один клик выставляет **обе** частоты так, чтобы получить нужную разность (например
`fL = 205, fR = 215 → 10 Гц`). Показывает, что получилось и что это значит.
Встроенный справочник частот — см. §6.

Пресеты — **двухуровневые**: сначала чип категории (состояние), внутри — конкретные
частоты. Реестр зафиксирован здесь, потому что он общий для Python и Swift и менять его
можно только по согласованию.

| `id` | EN | RU | пресеты, Гц |
|---|---|---|---|
| `sleep` | Sleep | Сон | 1, 2, 3 |
| `meditation` | Meditation | Медитация | 4, 5, 6 |
| `relaxation` | Relaxation | Расслабление | 8, 9, 10 |
| `awareness` | Awareness | Ясность | 11, 12 |
| `concentration` | Concentration | Сосредоточенность | 13, 14, 15 |
| `work` | Work | Работа | 16, 18, 20 |
| `sport` | Sport | Спорт | 22, 25, 28 |

Правила:

- **все пресеты внутри 1–30 Гц** (§2.1: это граница воспринимаемых биений);
- каждый пресет попадает **ровно в один** диапазон §6.1, без размытых границ. Диапазоны
  берутся из `frequencies.json` и читаются как полуинтервалы — иначе 4, 8, 13 и 30
  принадлежали бы сразу двум диапазонам:

  | Диапазон | Границы | Эквивалент в JSON |
  |---|---|---|
  | Delta | `[0.5, 4)` | `Delta 0.5–4 Hz` |
  | Theta | `[4, 8)` | `Theta 4–8 Hz` |
  | Alpha | `[8, 13)` | `Alpha 8–13 Hz` |
  | Beta | `[13, 30)` | `Beta 13–30 Hz` |
  | Gamma | `[30, 100]` | `Gamma 30–100 Hz` |

- подпись пресета — `<диапазон> <частота>`, локализуется: `Delta/Дельта`, `Theta/Тета`,
  `Alpha/Альфа`, `Beta/Бета`;
- **Gamma в пресеты не входит** — §2.1 ограничивает их 30 Гц. Из справочника при этом
  `Gamma 40 Hz` и `Gamma 30–100 Hz` не исчезают: правило касается только пресетов, §6
  хранит всё без отбора;
- диапазон по умолчанию при первом старте — `relaxation` (совпадает с
  `Session.preset_category`);
- существующие `PRESETS = (Delta 2, Theta 6, Alpha 10, Beta 20, Gamma 40)` в
  `main_window.py` заменяются реестром выше: все пять сами по себе лежат в верных
  диапазонах, но `Gamma 40` выходит за лимит пресетов в 30 Гц.

### F4 — Проверка наушников ⭐ обязательна
Как в §4: эвристика → перцептивный тест → диалог с возможностью продолжить.

### F5 — Сохранение сессий
Запомнить при перезапуске последний набор частот, громкость, флаг перестановки каналов,
**таймер** и **категорию пресета**.

- `TIMER_OFF = 0` — «без таймера, играть до остановки»
- `DEFAULT_TIMER_MINUTES = 15` — по §2.1 исследования длятся 5–15 минут
- `TIMER_CHOICES = (0, 5, 10, 15, 20, 30, 45, 60, 90, 120)` минут
- при чтении таймер зажимается в `0…1440`; больше суток — опечатка в файле настроек, а не
  пожелание

Экспорт сессии в WAV — опционально (P2); в `src/` писателя WAV нет, и придумывать его во
имя полноты не нужно.

### F6 — Установка через curl

## 6. Справочник частот

Всё содержимое сохраняется **без отбора и без ранжирования** (решение принято), но
оформляется в **категории** — иначе сотни значений превращаются в нечитаемую стену чисел.

Хранится как **данные** (не код): `src/binaural/data/frequencies.json`.

```json
{
  "version": 1,
  "categories": [
    {
      "id": "brainwave",
      "order": 1,
      "icon": "🧠",
      "color": "#6C8EEF",
      "label_en": "Brainwave Entrainment",
      "label_ru": "Мозговые волны",
      "description_en": "Entrainment by EEG brainwave band",
      "description_ru": "Синхронизация по диапазонам мозговых волн"
    }
  ],
  "frequencies": [
    {
      "id": "alpha-10",
      "category": "brainwave",
      "label": "Alpha 10 Hz",
      "beat_hz": 10.0,
      "carrier_hz": 200.0,
      "effect_en": "Relaxed alertness, calm focus, stress reduction",
      "effect_ru": "Расслабленная бдительность, спокойная концентрация, снижение стресса",
      "evidence": "well-studied",
      "source": "Peer-reviewed EEG literature on frequency-following response",
      "tags": ["focus", "relaxation"]
    }
  ]

```

- `beat_hz` — что подать на **разность**; `carrier_hz` — рекомендуемая несущая (по умолчанию 200)
- Диапазонные записи используют `beat_min` / `beat_max` вместо `beat_hz`
- `id` уникален глобально, формат `{category}-{значение}`
- Частоты указываются в **Гц**, десятичная точка (`.`), без пробелов

### Уровень обоснованности `evidence`

| Значение | Значок | Смысл |
|---|---|---|
| `well-studied` | 🟢 | есть рецензируемые исследования |
| `studied` | 🔵 | есть исследования, но меньше |
| `reported` | 🟡 | заявляется, исследований мало |
| `traditional` | 🟣 | из традиций и эзотерических практик |

Значок — **подсказка, а не фильтр**: ничего не прячется и не ранжируется.

### 6.3 Мозговые волны (нейросинхронизация)

| Диапазон | Частота биения | Состояние | Влияние на человека |
|---|---|---|---|
| **Delta** | 0.5–4 Гц | Глубокий сон без сновидений | Восстановление тканей, выброс гормона роста, укрепление иммунитета, самовосстановление организма |
| **Theta** | 4–8 Гц | Медитация, REM-сон, гипнагогия | Креативность, эмоциональная переработка, консолидация памяти, глубокая релаксация, доступ к подсознанию |
| **Alpha** | 8–13 Гц | Расслабленная бдительность | Снижение стресса, «поток», сосредоточенность без напряжения, рост серотонина, состояние перед засыпанием |
| **Beta** | 13–30 Гц | Активное мышление | Концентрация, бодрость, решение задач, энергия. Долгий высокий beta → тревожность, гипервозбуждение |
| **Gamma** | 30–100 Гц | Высшая когнитивная обработка | «Сшивание» восприятия в единое целое, инсайт, извлечение памяти, обострение восприятия. **40 Гц** изучается в исследованиях болезни Альцгеймера (нейросенсорная стимуляция) |

Типовые отдельные значения: `1.94` (глубокий сон), `4` (theta), `10` (alpha),

### 6.4 Резонанс Шумана

`7.83 Гц` — основной, плюс обертоны `14.3`, `20.8`, `27.3`, `33.8 Гц`.
Электромагнитный резонанс между поверхностью Земли и ионосферой, «электромагнитное
сердце планеты». Приписываемое влияние: ощущение заземления, уравновешенность,
нормализация биоритмов, устранение чувства дезориентации.

## 7. Интерфейс

Принципы: **максимально удобный**, в лучших традициях настольных приложений.
Нативные Qt-виджеты (не веб-вью), системный вид, стандартные хоткеи, HiDPI, светлая/тёмная тема.

### 7.1 Визуальный язык

Направление — **calm wellness**: мягкая лаванда как основа, приглушённый зелёный как

мысль, между карточками 16 px.

### 7.2 Правила доступности (обязательны)

- Контраст текста **≥ 4.5:1**, для `display`-чисел ≥ 3:1
- **Видимое фокус-кольцо** на любом интерактивном элементе, включая модалки — не убирать
- Минимум кликабельной области **44×44 px**
- Цвет **не единственный** носитель смысла: рядом со статусом — иконка и текст
  (`⚠ Speakers detected`, не просто жёлтая точка)
- Поддерживаются **reduced-motion** (в ОС) — пульсация биения отключается, остаётся
  статичный индикатор
- Светлая тема: серый по серому не используется
- Полная клавиатурная навигация, Tab по логичному порядку, Escape закрывает модалку

### 7.3 Иконки

Иконки — **SVG** (Lucide/Heroicons), не эмодзи в интерфейсе. Эмодзи допустимы только
внутри текста справочника (§6.1) как визуальные метки категорий — там это часть данных,
а не элементы управления.

### 7.4 Язык интерфейса

**English + Русский, переключается на лету** из меню *Вид → Язык*. Английский — исходный
язык: все строки пишутся по-английски и проходят через `i18n.tr()`, русский каталог лежит
в `locales/ru.py`. Выбор хранится в QSettings (`ui/language`); при первом запуске, пока
настройки нет, берётся локаль системы. Диалоги создаются заново при каждом открытии и
подхватывают язык сами, главное окно перечитывает свои подписи по сигналу `language_changed`.

### Главное окно

```
┌────────────────────────────────────────────────────────────────┐
│  Binaural                              ⚠ Speakers detected    │  ← статус
├────────────────────────────────────────────────────────────────┤
│                                                                │
│   LEFT EAR                          RIGHT EAR                 │
│   ┌──────────────────────┐         ┌──────────────────────┐    │
│   │      205.0  Гц       │         │      215.0  Гц       │    │  ← крупные
│   └──────────────────────┘         └──────────────────────┘    │    значения
│   ══════════●════════════          ═══════════●═══════════     │  ← слайдеры
│                                                                │
│              ┌────────────────────────────────┐                │
│              │      BEAT   10.0  Гц           │                │  ← ядро
│              │      ☐ Зафиксировать           │                │  ← разность —
│              │      CARRIER 210.0 Гц          │                │    только показание
│              └────────────────────────────────┘                │
│                                                                │
│   [ ▶ Play ]   Volume ════════●════      [ Save preset ]       │
├────────────────────────────────────────────────────────────────┤
│  Presets: [ Delta 2 ] [ Theta 6 ] [ Alpha 10 ] [ Beta 20 ] ... │  ← чипы
└────────────────────────────────────────────────────────────────┘
```

- Крупные читаемые частоты, точный ввод с клавиатуры, шаг 0.1
- **«Зафиксировать» (Lock difference)** — флажок рядом с `BEAT`. Пока включён, изменение
  одного канала двигает второй так, чтобы **знаковая** разность `fR − fL` оставалась той,
  что была в момент включения. Разность при этом остаётся **показанием, а не полем ввода**:
  поля для ввода разности нет, флажок фиксирует текущую.
  - пресет (F3) выставляет свою разность и **снимает** флажок, с короткой подсказкой;
  - если следование вывело бы второй канал за диапазон 1–20000 Гц, редактируемый канал
    **останавливается на границе** (показывается существующая подсказка о выходе за
    диапазон), а сама блокировка не нарушается и не снимается;
  - состояние флажка сохраняется вместе с сессией (§5 F5) и переживает перезапуск;
  - в Python-реализации флажка нет: поле `Session.difference_locked` читается как `False`
- **Значимая визуализация биения** — пульсирующий элемент на частоте разности
  (визуальное подтверждение, что «что-то происходит»)
- Пресеты — горизонтальные чипы, один клик выставляет обе частоты
- **Таймер воспроизведения** — значения из `TIMER_CHOICES`, 0 = выкл.; по истечении плавное
  затухание, чтобы остановка не была щелчком
- **Кнопка проверки наушников прямо в окне** — повторить §4 в любой момент, а не только при
  старте
- Индикатор состояния наушников всегда виден
- Space — play/stops, `↑/↓` — тонкая подстройка, `←/→` — переключение канала

### Диалоги
1. **Headphone check** при старте (§4)
2. **Perceptual L/R test** (§4.2)
3. **Preset editor** — сохранить текущий набор с названием
4. **Settings** — выбор языка (наряду с меню *Вид → Язык*), проверка наушников, таймер
5. **Help → Frequency reference** — полный справочник из §6, поиск и фильтр по категориям
6. **Help → About / Disclaimer**

### 8.1 Вторая реализация: `apple/`

Монорепо разделяет **исходники по продуктам**, а не по ОС:

| Где | Что |
|---|---|
| `src/`, `tests/`, `docs/` | общее: приложение на Python + Qt (сейчас macOS и Linux, дальше Windows) |
| `packaging/<ос>/`, `scripts/build_<ос>.*` | единственное место, где ОС действительно расходятся: `.desktop` / `Info.plist` / `.exe` |
| `apple/` | второй продукт на Swift — macOS и iOS, `xcodegen` + `xcodebuild` |

`apple/Sources/Core` не импортирует AppKit и SwiftUI, поэтому он собирается и тестируется и под
macOS, и под iOS. Паритет с Python доказывают тесты, а не приглядывание: те же 9 категорий и
99 записей, те же суммы по уровням обоснованности (68 🟣 / 12 🟢 / 11 🟡 / 8 🔵),
`pair(10 Гц, 200 Гц) → 195 / 205`, те же дефолты сессии.

Один справочник на всех: `apple/` получает `src/binaural/data/frequencies.json` фазой
copy-files, тесты читают его от `#filePath`. Вторая копия файла запрещена — её бы никто не
обновлял.

Когда Swift-версия выйдет на паритет, **релизная** сборка Python-приложения под macOS снимается
(`scripts/build_macos.sh`, `packaging/macos/Info.plist`, ветки `macos-*` в `install.sh`).
Сам Python-код остаётся: разработка идёт на Mac, поэтому `audio/platform/macos.py` и запуск из
исходников сохраняются.

## 9. Установка

```bash
curl -fsSL https://raw.githubusercontent.com/zeroscrypt/binaural/main/install.sh | sh
```

Что делает скрипт:

1. Определяет ОС и архитектуру (`macos-arm64`, `macos-x64`, `linux-x64`, `linux-arm64`)
2. Скачивает соответствующий релизный архив с GitHub Releases
3. Распаковывает в `~/.binaural/`
4. Кладёт симлинк `binaural` в `~/.local/bin` (добавляет в `PATH`, если надо)
5. Проверяет: `binaural --version`

Флаги: `--uninstall`, `--prefix=DIR`, `--version`, `--help`.
Зависимостей на машине пользователя **не нужно** — в архиве свой Python и Qt (PyInstaller).
Аналогично для Linux — тот же скрипт, другой архив.
