# apple/ — M2: the finished macOS application

> **Historical plan. M2 shipped.** The counts quoted below are the ones the plan was written
> against; where the reference has grown since, the line says so rather than pretending the
> plan is still ahead of the tree. Current state is `CONTEXT.md`.

M1 proved the core is *provably* equal to Python. M2 turns it into an app a person can
actually use: it makes sound, it has the interface from `docs/SPEC.md` §7, it checks
headphones at launch, it speaks English and Russian, and it sits in the menu bar.

**Target: macOS.** iOS must keep *compiling* (it is a stated direction) but this machine has
no simulator runtime and no signing identity, so iOS is not verifiable here and is not
allowed to block macOS work.

## Phase M2-a — a usable app: sound, window, language

### 1. Live audio

The oscillator API is already shaped for this; M1 left it unwired.

- `AVAudioEngine` + `AVAudioSourceNode` whose render block calls
  `StereoOscillator.render(frames:)` and writes interleaved samples.
- Take the real sample rate and channel layout from the device's format; do not assume 48000.
- Play/stop and frequency changes must be **click-free**: rely on the existing accumulating
  fade (`setFade(_:rampSeconds:)`), never jump gain or phase.
- Volume drives gain, not a post-hoc scale of the buffers.
- **The audio thread must not allocate, lock for long, or call into AppKit.** Frequencies,
  gain and pan change from the main thread while the callback reads them; design that
  handover deliberately and write down *why* it is correct. `StereoOscillator` was
  deliberately left non-`Sendable` in M1 — honour that. `@unchecked Sendable` is not an
  answer unless the comment next to it explains the memory-safety argument.

### 2. Internationalisation, first — not last

Every user-visible string goes through one function, EN as the source language, RU in a
single catalogue file ported from `src/binaural/locales/ru.py`. Doing this last means
rewriting every string twice; do it before the UI exists.

- `L10n.tr(_ key: String) -> String`: EN key missing → return the key itself (visible, not
  silent), RU missing → fall back to EN.
- Language is persisted and switchable **live**, without relaunching, like the Python app.
- Parity requirement: the RU catalogue carries the same keys as `ru.py` has today. A test
  must assert every key the app references has both languages — the Swift equivalent of
  `tests/test_i18n.py`.

### 3. Main window (§7)

- Two **independent** frequency controls, 1–20000 Hz, 0.1 Hz step, exact keyboard entry.
  Changing one never moves the other.
- Live `Beat: |fL − fR|` and `Carrier: (fL + fR) / 2`, with the §F1 hint when the beat falls
  outside 0.5–100 Hz.
- Play/stop (Space), volume, mute.
- Headphone-status indicator, always visible.
- Session restored on launch, saved on change.

**Acceptance:** the app launches, plays two tones, the beat readout tracks the inputs,
Space toggles, the language switches live, and the existing 73 tests stay green.

## Phase M2-b — everything else

### 4. Presets (§5 F3)

Implement the registry exactly as SPEC F3 fixes it: seven categories, 20 presets, all
1–30 Hz, each preset falling in exactly one band (the half-open boundaries F3 tabulates),
labels `<band> <beat>` localised. Two-level UI: category chips, presets inside the
selected one. The selected category feeds `Session.presetCategory`.

### 5. Frequency reference dialog (§6)

All entries in every category — **99 in 9 when this milestone was planned, 110 in 11 now**
(two researched categories, `substance` and `affect`, were approved later) — with search,
category filters, evidence badges, EN/RU. The catalogue code exists; this is the view over it.

### 6. Headphone check at launch (§4)

Heuristics first — port `audio/platform/macos.py` and `audio/headphones.py`: CoreAudio
device name and transport type (`bltn`, `blue`/`blea`, `dprt`). `kAudioDevicePropertyJackIsConnected`
is unusable on this Mac (err 2003332927) — Python already established that; do not retry it.

Then the perceptual L/R test if the heuristic is unsure, using the existing `setPan` hook.
Unconfirmed headphones → warn and **allow continuing** (SPEC §4.3), and remember that the
user acknowledged it.

### 7. Settings dialog and About (§7)

Settings: language (alongside *View → Language*), rerun headphone check, timer, volume.
About: project description and the §6.13 disclaimer, verbatim — no health claims invented.

### 8. Timer (§5 F5)

`Session.timerChoices`, 0 = off, default 15. Countdown visible; smooth fade-out at zero so
stopping is not a click.

### 9. Menu bar

Status item next to the clock from launch, showing/hiding the window and offering Quit —
the same role `TrayController` plays in Python.

### 10. Session storage

DESIGN §5.1 defers this decision to M2. Pick the location, implement it, and **record the
choice in `apple/DESIGN.md`** — Application Support is the obvious candidate; say why.

### 11. Release build

A Release `.app` that launches without Xcode. Signing stays ad-hoc/`CODE_SIGNING_ALLOWED=NO`
— there is no Apple Developer account, so Gatekeeper distribution is out of scope and must
not be faked.

## Rules

- `src/binaural/data/frequencies.json` stays the single copy (CONTRACT rule 10).
- No invented frequencies, effects or evidence levels; content comes from the JSON.
- No health claims beyond what `docs/FREQUENCIES.md` and §6.13 already say.
- Do not modify `src/`, `tests/`, `docs/`, `packaging/`, `scripts/`, `install.sh`. The only
  files you may change outside `apple/` are `.gitignore` (if a new artefact appears) —
  SPEC and CONTRACT edits go through the coordinator.
- Append M2 decisions and any new deviations to `apple/DESIGN.md`; do not rewrite M1's
  history there.
- Swift 6 language mode. Concurrency correctness is a deliverable, not an afterthought.

## Verify — paste the output into your report

```bash
cd apple
xcodegen generate
xcodebuild -project Binaural.xcodeproj -scheme BinauralCore -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO test
xcodebuild -project Binaural.xcodeproj -scheme Binaural -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project Binaural.xcodeproj -scheme Binaural-iOS -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

Plus a smoke test you actually perform: launch the built app, confirm the process stays
alive (`pgrep -f 'Binaural.app/Contents/MacOS'`), and kill it again. A build that crashes on
launch is not a passing build.

If the iOS Simulator runtime ever appears (`xcrun simctl list runtimes`), upgrade the iOS
build to a run-on-simulator check — but never let it gate macOS.

## Blocked, and out of M2

- App Store distribution, notarisation, installation on a physical iPhone — no Apple
  Developer account (`security find-identity` → 0).
- Running tests on the iOS Simulator — no runtime installed.
- WAV export — Python has no WAV writer either; SPEC §F5 calls it optional (P2).
- Android and any non-Apple mobile — explicitly out of scope (SPEC §12).
