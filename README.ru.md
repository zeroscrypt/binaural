# Binaural

![license](https://img.shields.io/badge/license-MIT-blue) ![platform](https://img.shields.io/badge/platform-macOS%20(Swift)%20%7C%20Linux%20(Python)-lightgrey) ![python](https://img.shields.io/badge/python-3.10%2B-blue) ![release](https://img.shields.io/badge/release-v0.1.0-blue)

**Две независимые частоты, одна воспринимаемая разность.**

Binaural — настольный генератор бинауральных биений. Вы задаёте одну частоту для левого уха и
другую для правого. Мозг сливает два тона и воспринимает третий, виртуальный тон с частотой,
равной **разности** между ними.

**macOS** получает нативное приложение на Swift из [`apple/`](apple/README.md), **Linux** —
приложение на Python/Qt из `src/`. Windows — в планах.

```
Левое ухо:   fL = 205.0 Гц
Правое ухо:  fR = 215.0 Гц
                    ↓
Воспринимается: 10.0 Гц   ← биение, его создаёт мозг, в сигнале его нет
```

Формально: `beat = |fL − fR|`, несущая = `(fL + fR) / 2`.

## Как это работает

Сигнал намеренно простой: два синусоидальных осциллятора, по одному на канал. Никаких эффектов,
никакой сцены, никакой музыки, никакой обработки.

```
   ┌─────────────┐      ┌─────────────┐
   │ Осциллятор  │      │ Осциллятор  │
   │  Л: 205 Гц  │      │ П: 215 Гц   │
   └──────┬──────┘      └──────┬──────┘
          │                    │
          └────────┬───────────┘
                   ▼
           Стереовыход ──► Левое ухо / Правое ухо
                   │
                   ▼
        Мозг слышит тон на частоте |fL − fR|
```

Тона 10 Гц **в аудиосигнале нет**. Каждое ухо получает обычный тон около 210 Гц. То «мерцание» с
частотой 10 Гц, которое вы можете воспринимать, — это разность двух каналов, вычисляемая внутри
вашей слуховой системы. Именно поэтому каждое ухо должно получать свою частоту и больше ничего.

## Почему наушники обязательны

Это не рекомендация. Это физическое условие, при котором метод вообще работает.

На колонках оба тона идут через один и тот же воздух и **смешиваются до того, как достигнут
ушей**. Оба уха получают одинаковую перемешанную волну, и мозгу не из чего вычислить разность.
Разность, а с ней и эффект, исчезает. Никакая настройка приложения это не исправит.

Наденьте наушники до того, как нажмёте play. Приложение проверяет устройство вывода при каждом
запуске и сообщает, если считает, что у вас колонки. Диалог с полным L/R-тестом показывается до
первого подтверждения, а вернуть его можно в любой момент из *Настроек* или из меню *Справка*.

## Установка

### macOS — нативное приложение

```bash
git clone https://github.com/zeroscrypt/binaural.git
cd binaural/apple
./build_release.sh          # собирает apple/dist/Binaural.app
open apple/dist/Binaural.app
```

Скрипт собирает Release во временный derived-data, копирует готовый бандл в
`apple/dist/Binaural.app`, сверяет положенный в него `frequencies.json` с единственной копией в
`src/` через `shasum` и удаляет дерево сборки. Xcode больше не нужен — это обычный `.app`,
который можно открыть двойным щелчком.

> **Приложение не подписано.** На машине сборки нет identity Apple Developer, поэтому сборка идёт
> с `CODE_SIGNING_ALLOWED=NO` и без нотаризации. Оно работает у того, кто его собрал; у любого
> другого Gatekeeper заблокирует первый запуск, обход — правый клик → *Открыть*. Полноценное
> распространение — подпись, нотаризация, App Store — требует аккаунта Apple Developer и не
> сделано. **v0.1.0 на GitHub — только исходники**: к релизу не прикреплено ни одного бинарника.

### Linux — одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/zeroscrypt/binaural/main/install.sh | sh
```

Скрипт определяет ОС и архитектуру, скачивает соответствующий архив релиза с GitHub Releases,
распаковывает его в `~/.binaural/`, кладёт симлинк `binaural` в `~/.local/bin` (добавляя его в
`PATH`, если нужно) и проверяет результат через `binaural --version`. Никакого Python или Qt на
вашей машине не требуется — в архиве свой runtime.

> **Важно:** Linux — единственная платформа, для которой этот скрипт ставит сборку на Python, и
> релизные архивы ещё не выходили. Если релиза нет, скрипт сам переходит на установку из
> исходников — это полностью поддерживаемый путь, а не ошибка.
>
> На macOS скрипт объясняет ситуацию и делает именно то, что нужно: macOS-продукт — приложение
> на Swift выше.

### Из исходников (любая платформа)

```bash
git clone https://github.com/zeroscrypt/binaural.git
cd binaural
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
.venv/bin/binaural
```

`pip install -e .` также ставит консольный скрипт `binaural`, поэтому точкой входа будет
`.venv/bin/binaural`. Этот путь полностью работает и на macOS: Python-версия по-прежнему
определяет устройства вывода через CoreAudio.

Подробности, включая ручную сборку и решение проблем, — в
**[docs/INSTALL.md](docs/INSTALL.md)**.

## Скриншоты

*Скриншоты будут добавлены здесь, когда завершится полировка интерфейса.* Ожидаемое содержимое:

- **Главное окно, светлая тема** — крупные значения частот слева и справа, два слайдера, метрики
  BEAT и CARRIER в центре, флажок *Зафиксировать* под разностью, кнопка play, громкость, таймер
  воспроизведения и двухуровневые чипы пресетов внизу.
- **Диалог проверки наушников** — предупреждение при обнаруженных колонках, с кнопками
  *Continue anyway* и *Retry check*.
- **Перцептивный тест L/R** — последовательность тон слева, затем справа, и вопрос «что вы
  услышали?».
- **Настройки** — язык, таймер, громкость и кнопка повторной проверки наушников.
- **Диалог справочника частот** — боковая панель категорий со счётчиками, поле поиска и карточка
  записи: название → частота → *Apply* → текст эффекта → значок обоснованности.

Пока файлов изображений нет, ссылки на них не вставлены, так что ничего не сломано.

## Возможности

Объём по спецификации проекта, в обеих реализациях. Что уже реализовано, а что ещё в работе, —
в разделе [Статус проекта](#статус-проекта).

- **Две независимые частоты** — отдельные поля и слайдеры для левого и правого канала, точный ввод
  с клавиатуры, шаг 0.1 Гц, диапазон 1–20000 Гц. Изменение левого канала никогда не двигает
  правый.
- **Живой расчёт разности и несущей** — `Beat: |fL − fR|` и `Carrier: (fL + fR) / 2` обновляются
  по мере ввода, с подсказкой, если разность выходит за обычный диапазон восприятия 0.5–100 Гц.
- **Воспроизведение без щелчков** — частота меняется без разрыва фазы, амплитуда нарастает и
  спадает плавно за десятки миллисекунд, `Space` — play/stop.
- **Двухуровневый реестр пресетов, 7 категорий / 20 пресетов** — сначала категория (Сон,
  Медитация, Релаксация, Осознанность, Концентрация, Работа, Спорт), затем пресет. Каждый пресет
  лежит в диапазоне 1–30 Гц и ровно в одной полосе мозговых волн, и один клик выставляет **обе**
  частоты вокруг несущей 200 Гц так, чтобы разность была биением: `fL = 200 − beat/2`,
  `fR = 200 + beat/2`. Выбранная категория запоминается между запусками.
- **Таймер воспроизведения** — 0 (выключен) или 5–120 минут из фиксированного списка, по
  умолчанию 15. Оставшееся время считается на экране, по истечении воспроизведение
  останавливается само.
- **«Зафиксировать» (Lock difference)** — включённый флажок двигает второй канал на столько же,
  на сколько изменён первый, поэтому знаковая разность остаётся там, куда её поставили. Пресет
  выставляет свою разность и снимает флажок; у границы диапазона 1–20000 Гц останавливается
  редактируемый канал, а не ломается сама блокировка. *Только в реализации на Swift — Python
  сохраняет флаг, но органа управления для него не имеет.*
- **Проверка наушников** — сначала эвристика по устройствам
  (Bluetooth/USB/HDMI/встроенные, имена портов), затем быстрый перцептивный тест левого/правого
  канала. Если каналы окажутся перепутаны, приложение запомнит это и поменяет вывод местами,
  чтобы разность была на нужной стороне. Эвристика выполняется на каждом запуске, диалог
  появляется до первого подтверждения, а повторить проверку можно в любой момент из *Настроек*
  или из меню *Справка*.
- **Настройки** — язык, таймер воспроизведения, громкость и кнопка проверки наушников; каждый
  орган управления пишет прямо в работающее окно.
- **Справочник частот, 9 категорий** — мозговые волны, резонанс Шумана, планетарные тоны,
  сольфеджио, эталоны настройки, исследовательские частоты, частоты Райфа, «частоты NASA»,
  исцеление и энергетика. Двуязычный (en/ru), с поиском и значком обоснованности у каждой записи.
  Подробности в **[docs/FREQUENCIES.md](docs/FREQUENCIES.md)**.
- **Светлая и тёмная тема**, нативные виджеты, HiDPI, полная навигация с клавиатуры.
- **Интерфейс на русском и английском**, переключается на лету — см. [Язык](#язык).
- **Две реализации, по продукту на платформу** — нативное приложение на Swift из
  [`apple/`](apple/README.md) собирается для macOS и iOS, Python/Qt-версия отсюда — для Linux,
  дальше Windows. Они делят файл справочника частот и API-контракт, но никогда — исходный код.

Вне объёма: 3D/HRTF-позиционирование, наложение на файлы или радио, анализатор спектра, запись
и стриминг, экспорт в WAV. iOS входит в объём через `apple/`, а не через Python; Android не
планируется.

## Язык

Интерфейс — **русский или английский**, переключается в меню приложения (*Вид → Язык*) или из
*Настроек*. Переключение применяется сразу, включая уже открытое окно и открытый диалог, а
выбор сохраняется по ключу `ui/language`, поэтому в следующий раз приложение откроется на том же
языке. При самом первом запуске настройки ещё нет, и приложение следует локали системы: русская
локаль — русский интерфейс. Обе реализации используют один и тот же ключ и один и тот же русский
текст: каталог Swift **генерируется** из Python-каталога (`src/binaural/locales/ru.py`), и если
они разойдутся по составу переведённых строк, тест уронит сборку.

Справочник частот двуязычен независимо от языка интерфейса: названия категорий и описания
эффектов берутся из `frequencies.json`, где лежат обе версии, а второй язык остаётся
доступным по наведению.

## Справочник частот

Приложение поставляется со статическим справочником из **99 записей в 9 категориях**, который
хранится как данные в `src/binaural/data/frequencies.json` и показывается в приложении с
поиском, счётчиками по категориям и значком обоснованности. Этот файл — единственная копия
справочника в репозитории, её же читает приложение на Swift.

Полные таблицы — в **[docs/FREQUENCIES.md](docs/FREQUENCIES.md)**.

Пять диапазонов ЭЭГ — та часть справочника, за которой стоят реальные исследования:

| Диапазон | Разность | Обычно связывают с | Обоснованность |
|---|---|---|---|
| Delta | 0.5–4 Гц | Глубокий сон без сновидений | 🟢 рецензируемая литература по ЭЭГ |
| Theta | 4–8 Гц | Медитация, REM-сон, гипнагогия | 🟢 рецензируемая литература по ЭЭГ |
| Alpha | 8–13 Гц | Расслабленная бдительность | 🟢 рецензируемая литература по ЭЭГ |
| Beta | 13–30 Гц | Активное мышление | 🟢 рецензируемая литература по ЭЭГ |
| Gamma | 30–100 Гц | Высшая когнитивная обработка | 🟢 рецензируемая литература по ЭЭГ |

В справочник ничего не отбирается и не ранжируется. Записи из эзотерических, энергетических и
альтернативных практик помечены 🟣 и остаются видимыми, а не скрытыми, — чтобы было видно, что
именно утверждается и откуда это взято.

## Что говорит наука

Коротко: акустический эффект реален и измерим, а поведенческие утверждения остаются спорными.

**Относительно хорошо установлено**

- Воспринимаемое биение лежит примерно в диапазоне **1–30 Гц**, который совпадает с основными
  диапазонами ЭЭГ. За пределами этого диапазона воспринимать, скорее всего, нечего.
- **Низкая несущая работает лучше.** Несущая около 400 Гц даёт измеримый отклик, выше примерно
  3 кГц эффект не обнаруживается. Пик чувствительности отмечен в районе 250 Гц. Поэтому в
  приложении дефолтная несущая 200 Гц и предупреждение при уходе существенно выше.
- В ЭЭГ существуют два измеримых ответа: **frequency-following response (FFR)**, привязанный к
  несущей, и **auditory steady-state response (ASSR)** на частоте биения. Оба подтверждены
  экспериментально.
- **Шум маскирует эффект.** Белый шум в сигнале ослабляет энтрейнмент, поэтому приложение
  поставляется без шума.
- Длительность стимуляции в исследованиях обычно **5–15 минут**.

**Спорно**

- Результаты противоречивы. В систематическом обзоре 2023 года по 14 релевантным исследованиям
  **6 поддержали гипотезу энтрейнмента, 9 — нет** или были неубедительными. Индивидуальные
  результаты отличаются у разных людей.
- Находки FFR/ASSR показывают, что мозг *отслеживает* биение. Сами по себе они не доказывают,
  что прослушивание меняет сон, настроение, концентрацию или здоровье.

Итак: исследования позволяют говорить, что явление существует, некоторые пользователи отмечают
субъективный эффект, а данные о том, что этот эффект *делает*, остаются смешанными. Ничего из
этого не является обещанием, и приложение не делает никаких терапевтических заявлений. Более
длинная версия — в **[docs/SCIENCE.md](docs/SCIENCE.md)**.

Источники: [систематический обзор 2023 (PMC10198548)](https://pmc.ncbi.nlm.nih.gov/articles/PMC10198548/) ·
[Reznik & Allen 2020, *eNeuro*](https://www.eneuro.org/content/7/2/ENEURO.0232-19.2020) ·
[Garcia-Argibay et al. 2025, *Scientific Reports*](https://www.nature.com/articles/s41598-025-88517-z) ·
а также Pratt et al. 2009 (ERP) и Schwarz & Taylor по данным о несущей частоте.

## Требования

**Приложение для macOS** — macOS 12 или новее. `apple/build_release.sh` больше ничего не
требует, а готовый `.app` запускается сам по себе.

**Приложение для Linux** — Linux (x86_64 или arm64) с работающей сессией PulseAudio или
PipeWire. Релизный архив несёт свой Python и Qt; установке из исходников нужен Python 3.10 или
новее (разрабатывалось на 3.12) и `pip`, PySide6 6.5+ (Essentials и Addons) ставится
автоматически, `numpy` приходит с экстра `dev`.

**Сборка реализации на Swift (`apple/`)** — Xcode 27 (Swift 6.4) и `xcodegen`
(`brew install xcodegen`). Аккаунт Apple Developer для сборки и тестов не нужен — он нужен для
развёртывания на физический iPhone.

## Разработка

```bash
git clone https://github.com/zeroscrypt/binaural.git
cd binaural
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
```

Тесты:

```bash
.venv/bin/python -m pytest
```

Запуск приложения из рабочей копии:

```bash
.venv/bin/binaural
```

Слои разделены намеренно: `core/` — чистая математика без импорта Qt (тестируется без
аудиоустройств), `audio/` — перечисление устройств и детект наушников, `ui/` — только отображение.
Общаются они через сигналы Qt. API-контракт описан в `docs/CONTRACT.md`.

На headless-системе Linux приложению нужен offscreen-платформа Qt:

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest
```

### Нативная реализация на Swift (`apple/`)

Это сборка для macOS (и iOS). Она читает тот же `src/binaural/data/frequencies.json` — второй
копии справочника в репозитории сознательно нет — и соблюдает тот же API-контракт.

```bash
cd apple
xcodegen generate
xcodebuild -project Binaural.xcodeproj -scheme BinauralCore \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO test    # 208 тестов core
xcodebuild -project Binaural.xcodeproj -scheme Binaural \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO test    # + 135 тестов окна
./build_release.sh                                              # apple/dist/Binaural.app
```

`CODE_SIGNING_ALLOWED=NO` здесь обязателен: сертификата Apple Developer нет. Что вошло в вехи,
что ещё открыто и какие ограничения накладывает подпись — в
[apple/README.md](apple/README.md) и `apple/DESIGN.md`.

## Планы

**Сделано** — всё, что план ниже когда-то перечислял как ожидающее, теперь в дереве и покрыто
тестами в обеих реализациях: главное окно с живым расчётом разности и несущей, двухуровневый
реестр пресетов, таймер воспроизведения, диалоги проверки наушников и L/R-теста, справочник
частот с поиском и значками обоснованности, диалог настроек, светлая/тёмная тема, горячие клавиши
и правила доступности из спецификации.

**Дальше**

- **Релизные архивы для Linux** — упаковка на месте, но ничего не собрано и не прикреплено к
  релизу. `v0.1.0` — только исходники.
- **Windows** — WASAPI-бэкенд за `audio/platform/`, сборка PyInstaller, `install.ps1`
- Резервный вывод через `miniaudio` там, где недоступен `QAudioSink`
- Экспорт сессии в WAV — сознательно отсутствует в обеих реализациях, спецификация считает его
  необязательным
- **iOS** — схема собирается и линкуется, но не запускалась ни разу: на этой машине нет runtime
  симулятора. `xcodebuild -downloadPlatform iOS` превращает это в настоящую проверку

**Честные ограничения**

- Приложение для macOS **не подписано** — на машине сборки нет identity Apple Developer, нет
  нотаризации и App Store. Gatekeeper заблокирует его любому, кроме сборщика.
- Перцептивный L/R-тест и его краевые случаи может оценить только человек в наушниках.
