## О проекте

<pre align="center">
Левое ухо:   fL = 205.0 Гц
Правое ухо:  fR = 215.0 Гц
                    ↓
Воспринимается: 10.0 Гц   ← биение, его создаёт мозг, в сигнале его нет
</pre>

Binaural — настольный генератор бинауральных биений. Вы задаёте одну частоту для левого уха и
другую для правого. Мозг сливает два тона и воспринимает третий, виртуальный тон с частотой,
равной **разности** между ними. Формально:

```
beat    = |fL − fR|
carrier = (fL + fR) / 2
```

**macOS** получает нативное приложение на Swift из [`apple/`][apple-dir]. **Linux** —
приложение на Python/Qt из [`src/`][src-dir]. Windows — в планах.

Сигнал намеренно простой: два синусоидальных осциллятора, по одному на канал. Никаких эффектов,
никакой сцены, никакой музыки, никакой обработки.

```
   ┌─────────────┐      ┌─────────────┐
   │ Осциллятор  │      │ Осциллятор  │
   │  Л: 205 Гц  │      │ П: 215 Гц   │
   └──────┬──────┘      └──────┬──────┘
          │                    │
          └────────┬───────────┘
                   ▼
           Стереовыход ──► Левое ухо / Правое ухо
                   │
                   ▼
        Мозг слышит тон на частоте |fL − fR|
```

Тона 10 Гц **в аудиосигнале нет**. Каждое ухо получает обычный тон около 210 Гц. То «мерцание» с
частотой 10 Гц, которое вы можете воспринимать, — это разность двух каналов, вычисляемая внутри
вашей слуховой системы. Именно поэтому каждое ухо должно получать свою частоту и больше ничего.

### Почему наушники обязательны

Это не рекомендация. Это физическое условие, при котором метод вообще работает.

На колонках оба тона идут через один и тот же воздух и **смешиваются до того, как достигнут
ушей**. Оба уха получают одинаковую перемешанную волну, и мозгу не из чего вычислить разность.
Разность, а с ней и эффект, исчезают. Никакая настройка приложения это не исправит.

Наденьте наушники до того, как нажмёте «Воспроизвести». Приложение проверяет устройство вывода
при каждом запуске и сообщает, если считает, что у вас колонки. Диалог с полным L/R-тестом
показывается до первого подтверждения, а вернуть его можно в любой момент из *Настроек* или из
меню *Справка*.

### На чем собрано

- **Приложение для macOS** — Swift 6.4 в строгом режиме конкурентности, `AVAudioEngine` и
  CoreAudio для вывода, `BinauralCore` как тестируемая среда, AppKit для окна и оболочка на
  SwiftUI для iOS ([`apple/`][apple-dir], Xcode и `xcodegen`)
- **Приложение для Linux** — Python 3.10+ и PySide6 (Qt 6); вывод через `QAudioSink` из
  QtMultimedia, `pytest` для тестов ([`src/`][src-dir] и [`tests/`][tests-dir])
- **Общее у обеих** — один файл справочника частот (`frequencies.json`) и один API-контракт
  ([`docs/CONTRACT.md`][contract]). Данные и поведение общие, исходный код — никогда.

## Что такое бинауральные биения?

В одной фразе: **тон, которого нет в сигнале.** Две слегка различающиеся частоты идут в два
уха, и слушающий слышит третью — их разность, — которой нет нигде в аудиоданных. Из этого
факта вытекает каждое проектное решение в приложении.

### Явление

Подайте `205 Гц` в левое ухо и `215 Гц` в правое одновременно, каждое по своему каналу. Никто не
слышит «205 и 215». Слышен один ровный тон около 210 Гц — **несущая**, — а внутри него что-то
движется: медленный пульс, мерцание, дрожание с частотой 10 Гц. Это дрожание и есть
бинауральное биение.

```
beat    = |fL − fR|          # 10 Гц в примере выше
carrier = (fL + fR) / 2      # 210 Гц — высота, которую вы действительно слышите как тон
```

Несущая — это высота тона, биение — это движение. Это независимые числа: одна и та же несущая
200 Гц может нести биение и 1 Гц, и 25 Гц, и это будут разные ощущения.

### Где это происходит в мозге

Оба сигнала идут по слуховому нерву в **медиальное верхнее оливное ядро (MSO)** — небольшое
ядро в стволе мозга и первая станция слухового пути, где вообще сравниваются два уха. Выше
него, в таламусе и в слуховой коре, мозг всё ещё работает с одним слитым потоком. MSO замечает,
что левый вход совсем немного медленнее правого, и отвечает с частотой их разности.

Последствие — самая странная часть:

> **Частоты биения в аудиосигнале нет.** Каждое ухо получает обычную синусоиду. Ни в одном
> канале нет 10 Гц. Разность существует только после того, как два сигнала встретились в мозгу
> слушающего.

То есть это внутренний звук: его нет нигде как форма волны, и микрофон у уха его не найдёт,
потому что разность создаётся дальше по цепи, собственными схемами слушающего. Приложение тоже
не может подделать её за вас — поэтому это генератор двух каналов и ничего больше.

### Немного истории

- **1839 — Генрих Вильгельм Дове**, прусский физик, публикует это явление: два чистых тона
  немного разной частоты, поданные раздельно и одновременно в два уха, воспринимаются как
  порождающие иллюзорные биения между собой. Ему наушники не понадобились — два камертона и
  трубка в каждое ухо делают то же самое, ведь важно только одно: два пути остаются раздельными.
- Больше чем на четверть века это остаётся любопытством в акустике.
- **1973 — Джеральд Остер** публикует *«Auditory Beats in the Brain»* в журнале
  *Scientific American*. Именно эта статья сделала эффект широко известным и превратила его в
  исследовательскую программу. Предметом работы Остера было устройство слуховой системы, а не
  то, что лечат бинауральные биения.

### Пять диапазонов мозговых волн

**Мозговая волна** — это ритмическая электрическая активность нейронов, которую записывают на
коже головы как ЭЭГ и делят по частоте на именованные диапазоны. О пяти из них обычно и
говорит этот метод:

| Диапазон | Биение | Обычно связывают с |
|---|---|---|
| **Delta** | 0.5–4 Гц | Глубокий сон без сновидений; физическое восстановление, выброс гормона роста, поддержка иммунитета |
| **Theta** | 4–8 Гц | Медитация, REM-сон, сонное состояние на пути ко сну; творчество, консолидация памяти |
| **Alpha** | 8–13 Гц | Расслабленная бдительность — бодрствовать, но без напряжения; снижение стресса, устойчивое внимание, состояние перед сном |
| **Beta** | 13–30 Гц | Активное мышление; концентрация, бдительность, решение задач. Длительное воздействие на высоком конце сопровождается перевозбуждением и тревожностью |
| **Gamma** | 30–100 Гц | Высшая когнитивная обработка, связывание восприятия в единое целое; 40 Гц отдельно изучаются в исследованиях нейродегенерации |

Эти пять диапазонов — та часть [справочника частот](#справочник-частот), за которой стоят
настоящие исследования: у каждого значок 🟢, рецензируемая литература по ЭЭГ.

Совпадение с тем, что вообще воспринимается, не случайно. Биения воспринимаются примерно в
диапазоне **1–30 Гц**, а это ровно диапазон амплитудной модуляции, за которым может следить
непрерывный тон: ниже примерно 1 Гц флуктуация слишком медленная, чтобы её отследить, а выше
примерно 30 Гц разность перестаёт восприниматься как биение и становится отдельным тоном. Delta,
theta, alpha и beta поэтому попадают внутрь окна. **Gamma — в основном нет**, и именно поэтому
20 пресетов заканчиваются на 30 Гц, хотя записи диапазона gamma в справочнике остаются.

Одна оговорка, прямо: сами диапазоны и то, с чем их связывают, не оспариваются. Спорным является
следующий шаг — что биение 10 Гц *захватывает* альфа-активность и тем самым даёт
поведенческие эффекты, свойственные альфе. *Энтрейнмент* — это название гипотезы о том, что
внешний ритм утягивает за собой собственный ритм мозга, как два маятника на одной доске
входят в резонанс.

### Что на самом деле показывают данные

**Надёжно.**

- Явление **реально и измеримо**. На скальповой ЭЭГ записываются два ответа:
  **frequency-following response (FFR)**, привязанный к несущей, и **auditory steady-state
  response (ASSR)**, возникающий на частоте биения. Оба подтверждены экспериментально. Мозг
  измеримо отслеживает биение.
- **Низкие несущие работают лучше.** Отклик измерим при несущей около 400 Гц, выше примерно
  3 кГц он становится ненадёжным, а чувствительность, по-видимому, достигает пика около 250 Гц.
- **Шум маскирует эффект.** Широкополосный шум в сигнале ослабляет отклиок: с шумом он
  измеримо меньше, чем без него.
- **Не все воспринимают биение**, а среди тех, кто воспринимает, интенсивность отличается
  сильно.

**Спорно.**

- **Систематический обзор 2023 года** рассмотрел 14 релевантных исследований: **6 поддержали
  гипотезу энтрейнмента, 9 — нет или были неубедительными.** Исследования при этом измеряют
  разное — маркеры ЭЭГ, субъективные отчёты, качество сна, когнитивные показатели, — поэтому их
  трудно сравнивать напрямую.
- **Отслеживание — не то же самое, что польза.** Находки FFR/ASSR показывают, что слуховая
  система *следует* за биением. Сами по себе они не показывают, что прослушивание улучшает сон,
  настроение, концентрацию или здоровье. Для этого шага нужны свои данные — и именно тут
  исследования расходятся.
- **Значительная часть популярных материалов вообще не научная.** Записи 🟣 и 🟡 в справочнике
  приходят из эзотерических, энергетических и альтернативных практик. «Восстановление ДНК»,
  детоксикация и рекомендации агентств — это утверждения, а не результаты.

Итак: явление реально, субъективные сообщения об эффекте обычны, а утверждение, что он *делает*
что-то конкретное с вами, остаётся спорным — это область с действительно неоднозначными
данными. Более длинная версия со всеми источниками — в разделе [Что говорит
наука](#что-говорит-наука) и в **[`docs/SCIENCE.md`][science]**. К всему сказанному выше
применим [Дисклеймер](#дисклеймер).

### Почему наушники обязательны физически

На колонках оба тона выходят из одной коробки в один и тот же воздух, а воздух складывает
формы волн: две частоты **смешиваются до того, как достигнут ушей**. Оба уха получают одну и ту
же перемешанную волну, в сигнале больше нет отдельных `fL` и `fR`, которые можно разделить, у
MSO нет ничего сравнивать — и биение исчезает. Не становится тише, а именно исчезает, потому
что сравнивать больше нечего.

Единственное требование — сохранить раздельность двух путей. В 1839 хватило двух камертонов и
двух трубок; наушники — это та же схема, просто у всех под рукой. Никакая настройка этого
приложения не восстановит эффект на колонках. Что приложение делает на этот счёт — в разделе
[Почему наушники обязательны](#почему-наушники-обязательны), а если биение ожидаемо, а его
нет — в [Решении проблем](#решение-проблем).

### Что приложение делает с этим

Каждый вывод выше имеет следствие в коде:

| Решение | Почему |
|---|---|
| Две независимые частоты, по одной на канал, больше ничего | Разность должна вычисляться мозгом слушающего. Приложение не может её подделать и не пытается |
| Несущая по умолчанию **200 Гц** | Отклик измерим около 400 Гц, ненадёжен выше ~3 кГц, пик чувствительности около 250 Гц |
| **Никакого слоя шума** | Широкополосный шум ослабляет эффект |
| Таймер по умолчанию **15 минут** с плавным затуханием | Сессии в литературе длятся 5–15 минут |
| **20 пресетов, все внутри 1–30 Гц**, ровно по одному диапазону | Диапазон восприятия. Gamma остаётся в справочнике, но не в пресетах: пресеты заканчиваются на 30 Гц |
| `BEAT` и `CARRIER` видны в реальном времени всегда | Чтобы видеть, что на самом деле генерируется, а не верить на ярлык |
| Подсказка, когда разность выходит за **0.5–100 Гц** | Та же мысль — сказать, когда числа за пределами диапазона, где биение стоит ожидать |
| У всех **110 записей справочника** есть значок обоснованности | 🟢 12 well-studied, 🔵 16 studied, 🟡 14 reported, 🟣 68 traditional. Ничего не скрыто, ничего не ранжировано, эзотерика помечена, а не выброшена |

Полные таблицы по последней строке — в **[`docs/FREQUENCIES.md`][frequencies]**.

## Возможности

- **Никакой настройки, чтобы что-то услышать.** Два числа, одна кнопка. Никаких аудиофайлов, ни
  цепочек обработки, никакого импорта.
- **Вы всегда знаете, что именно слышите.** `BEAT` и `CARRIER` обновляются по мере ввода, с
  подсказкой, если разность выходит за обычный диапазон восприятия 0.5–100 Гц.
- **Двадцать пресетов, семь категорий, один клик.** Выберите категорию, выберите пресет — и обе
  частоты выставятся вокруг несущей 200 Гц так, чтобы разность была ровно биением.
- **Сессия заканчивается сама.** Таймер воспроизведения останавливает тон, когда время вышло, —
  можно уснуть под него.
- **Настройка без щелчков.** Смена частоты не разрывает фазу, переходы плавные, а «Зафиксировать»
  даёт настроить одно ухо руками, пока второе следует за ним.
- **Приложение предупредит до того, как станет тихо.** Проверка наушников идёт при каждом
  запуске, а перцептивный тест левого/правого канала ловит перепутанные каналы и меняет вывод
  местами.
- **Справочник, который показывает свои источники.** 110 записей в 11 категориях, у каждой
  значок обоснованности, поиск и два языка — включая те утверждения, которые традиция и фольклор,
  а не исследование.

## Установка

### Требования

| Платформа | Что нужно |
|---|---|
| **macOS** | macOS 12 или новее. Для сборки: Xcode (Swift 6.4) и `xcodegen` (`brew install xcodegen`). Аккаунт Apple Developer не нужен. |
| **Linux** | Linux (x86_64 или arm64) с работающей сессией PulseAudio или PipeWire. Из исходников: Python 3.10+ (разрабатывалось на 3.12) и `pip`. PySide6 6.5+ ставится автоматически. |

### macOS — нативное приложение

```bash
git clone https://github.com/zeroscrypt/binaural.git
cd binaural/apple
./build_release.sh          # собирает apple/dist/Binaural.app
open apple/dist/Binaural.app
```

`build_release.sh` собирает Release во временный derived-data, копирует готовый бандл в
`apple/dist/Binaural.app`, сверяет положенный в него `frequencies.json` с единственной копией в
`src/` через `shasum` и удаляет дерево сборки. Xcode больше не нужен — это обычный `.app`,
который можно открыть двойным щелчком. С флагом `--smoke` скрипт ещё и запустит собранное
приложение и убьёт его — так ловится падение при старте. Что вошло в вехи и какие ограничения
накладывает подпись, написано в [`apple/README.md`][apple-readme].

> **Приложение не подписано.** На машине сборки нет identity Apple Developer, поэтому сборка идёт
> с `CODE_SIGNING_ALLOWED=NO` и без нотаризации. Оно работает у того, кто его собрал; у любого
> другого Gatekeeper заблокирует первый запуск, обход — правый клик → *Открыть*. Полноценное
> распространение — подпись, нотаризация, App Store — требует аккаунта Apple Developer и не
> сделано. **v0.1.0 на GitHub — только исходники**: к релизу не прикреплено ни одного бинарника,
> поэтому на macOS установка — это собрать самому.

### Linux — одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/zeroscrypt/binaural/main/install.sh | sh
```

Скрипт определяет ОС и архитектуру, скачивает соответствующий архив релиза, распаковывает его в
`~/.binaural/`, кладёт симлинк `binaural` в `~/.local/bin` (добавляя его в `PATH`, если нужно) и
проверяет результат через `binaural --version`. Никакого Python или Qt на вашей машине не
требуется — в архиве свой runtime.

Полезные флаги: `--dry-run` печатает каждый шаг и ничего не меняет, `--uninstall` удаляет
установку, `--help` показывает остальные. Если скрипт хочется сначала прочитать, а не запустить,
скачайте его:

```bash
curl -fsSLO https://raw.githubusercontent.com/zeroscrypt/binaural/main/install.sh
less install.sh
sh install.sh --dry-run
```

> **Важно:** Linux — единственная платформа, для которой этот скрипт ставит сборку на Python, и
> релизные архивы ещё не выходили. Если релиза нет, скрипт сам переходит на установку из
> исходников — это полностью поддерживаемый путь, а не ошибка.
>
> На macOS скрипт объясняет ситуацию и делает именно то, что нужно: macOS-продукт — приложение
> на Swift выше.

cd binaural
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"

## Как пользоваться

Три шага, по порядку.

### Сначала наушники

Запустите приложение, уже надев наушники. Если устройство вывода выглядит как колонки,
приложение скажет об этом и предложит проверку; см. [Почему наушники
обязательны](#почему-наушники-обязательны).

### Две частоты

В окне по одному органу управления на ухо: крупное значение, слайдер и поле, в которое можно
ввести число с клавиатуры. Двигаете один — второй остаётся ровно там, где был. Диапазон
1–20000 Гц, шаг 0.1 Гц.

В центре `BEAT` — это разность, а `CARRIER` — среднее двух частот. Начните с примера: 205 Гц
слева, 215 Гц справа — получится биение 10 Гц на несущей 210 Гц.

### Нажмите «Воспроизвести»

«Воспроизвести» запускает тон, «Остановить» завершает, `Space` переключает между ними. `↑`/`↓`
двигают активный канал на 0.1 Гц, `←`/`→` переключают ухо. Частоты можно менять на ходу
воспроизведения без щелчка — фаза непрерывна, а амплитуда меняется плавно.

Что есть в окне: два регулятора частоты, метрики BEAT и CARRIER с флажком «Зафиксировать» под
разностью, кнопка воспроизведения, громкость, таймер воспроизведения с обратным отсчётом и
двухуровневые чипы пресетов внизу.

### Пресеты

Семь категорий — Сон, Медитация, Релаксация, Осознанность, Концентрация, Работа, Спорт — всего
20 пресетов. Каждый пресет лежит в диапазоне 1–30 Гц и ровно в одной полосе мозговых волн, и
один клик выставляет **обе** частоты вокруг несущей 200 Гц так, чтобы разность была биением:
`fL = 200 − beat/2`, `fR = 200 + beat/2`. Выбранная категория запоминается между запусками.

«Сохранить пресет» запоминает текущую пару частот для следующего запуска.

### Таймер

0 означает «таймер выключен» — играть, пока не остановите. Иначе выбирается 5, 10, 15, 20, 30, 45,
60, 90 или 120 минут; по умолчанию 15. Оставшееся время считается на экране, по истечении
воспроизведение останавливается само.

### «Зафиксировать»

Включённый флажок двигает второй канал на столько же, на сколько изменён первый, поэтому
знаковая разность остаётся там, куда её поставили. У границы диапазона 1–20000 Гц
останавливается редактируемый канал, а не ломается сама блокировка. Пресет выставляет свою
разность и снимает флажок.

### Справочник в приложении

Открывается из *Справка → Справочник частот…* (`Ctrl+O` / `⌘O`). Слева боковая панель категорий
со счётчиками, сверху поле поиска, а в каждой записи: название → частота → «Применить» → текст
эффекта → значок обоснованности → источник. «Применить» выставляет обе частоты из записи. Сам
диалог двуязычен независимо от языка интерфейса.

### Настройки и язык интерфейса

В *Настройках* (`Ctrl+,` / `⌘,`) есть язык интерфейса, таймер по умолчанию, громкость и кнопка
повторной проверки наушников. Каждый орган управления пишет прямо в работающее окно.

Интерфейс — **русский или английский**, переключается в меню *Вид → Язык* или из *Настроек*.
Переключение применяется сразу, включая уже открытое окно и открытый диалог, а выбор
сохраняется по ключу `ui/language`. При самом первом запуске настройки ещё нет, и приложение
следует локали системы. Обе реализации используют один и тот же ключ и один и тот же русский
текст: каталог Swift **генерируется** из Python-каталога (`src/binaural/locales/ru.py`), и если
они разойдутся по составу переведённых строк, тест уронит сборку.

В остальном: *Справка → Проверить наушники…* (`Ctrl+Shift+H`) повторяет проверку устройства и
перцептивный L/R-тест, а *Справка → О программе* (`Ctrl+Shift+I`) содержит описание и
дисклеймер.

## Что говорит наука

Коротко: акустический эффект реален и измерим, а поведенческие утверждения остаются спорными.

**Относительно хорошо установлено**

- Воспринимаемое биение лежит примерно в диапазоне **1–30 Гц**, который совпадает с основными
  диапазонами ЭЭГ. За пределами этого диапазона воспринимать, скорее всего, нечего.
- **Низкая несущая работает лучше.** Несущая около 400 Гц даёт измеримый отклик, выше примерно
  3 кГц эффект не обнаруживается. Пик чувствительности отмечен в районе 250 Гц. Поэтому в
  приложении дефолтная несущая 200 Гц и предупреждение при уходе существенно выше.
- В ЭЭГ существуют два измеримых ответа: **frequency-following response (FFR)**, привязанный к
  несущей, и **auditory steady-state response (ASSR)** на частоте биения. Оба подтверждены
  экспериментально.
- **Шум маскирует эффект.** Белый шум в сигнале ослабляет энтрейнмент, поэтому приложение
  поставляется без шума.
- Длительность стимуляции в исследованиях обычно **5–15 минут**.

**Спорно**

- Результаты противоречивы. В систематическом обзоре 2023 года по 14 релевантным исследованиям
  **6 поддержали гипотезу энтрейнмента, 9 — нет** или были неубедительными. Индивидуальные
  результаты отличаются у разных людей.
- Находки FFR/ASSR показывают, что мозг *отслеживает* биение. Сами по себе они не доказывают,
  что прослушивание меняет сон, настроение, концентрацию или здоровье.

Итак: исследования позволяют говорить, что явление существует, некоторые пользователи отмечают
субъективный эффект, а данные о том, что этот эффект *делает*, остаются смешанными. Ничего из
этого не является обещанием, и приложение не делает никаких терапевтических заявлений. Более
длинная версия — в **[`docs/SCIENCE.md`][science]**.

Источники: [систематический обзор 2023 (PMC10198548)][pmc-review] ·
[Reznik & Allen 2020, *eNeuro*][ez] ·
[Garcia-Argibay et al. 2025, *Scientific Reports*][sci-rep] ·
а также Pratt et al. 2009 (ERP) и Schwarz & Taylor по данным о несущей частоте.

## Решение проблем

Полные подробности и вся таблица случаев — в **[`docs/INSTALL.md`][install]**. Вот те, что
встречаются на самом деле.

### `qt.qpa.plugin: Could not load the Qt platform plugin "xcb"`

Qt не может открыть окно. На обычной сессии это обычно означает недостающие системные библиотеки
для плагина темы — xcb-плагину нужен десяток пакетов X11:

```bash
# Debian/Ubuntu
sudo apt-get install -y libxcb-cursor0 libxkbcommon-x11-0 libxcb-xinerama0 libxcb-icccm4 \
  libxcb-image0 libxcb-keysyms1 libxcb-randr0 libxcb-render-util0 libxcb-shape0 libxcb-xkb1 \
  libegl1 libgl1 libglib2.0-0

# Fedora
sudo dnf install -y xcb-util-cursor xcb-util-keysyms xcb-util-wm xcb-util-image \
  libxkbcommon-x11 mesa-libEGL mesa-libGL

# Arch
sudo pacman -S --needed xcb-util-cursor xcb-util-keysyms xcb-util-wm xcb-util-image \
  libxkbcommon-x11 mesa
```

### Qt не стартует на машине без дисплея

Без дисплея открывать нечего. Для тестов, CI и всего неинтерактивного:

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest
```

`offscreen` оставляет Qt полностью работоспособным, кроме самого окна. Это не обходной путь для
запуска интерфейса через удалённую сессию — для этого нужна проброс X11 или сессия Wayland.

### Нет звука, либо в ошибке упоминается `QAudioSink`

`QAudioSink` приходит из PySide6-Addons. Если установлен только PySide6-Essentials, звуковой
движок не запустится.

```bash
.venv/bin/python -m pip install "PySide6-Addons>=6.5"
```

Затем проверьте, что платформа вообще может открыть устройство:

```bash
pactl list short sinks
pactl get-default-sink
```

Если sink существует и PulseAudio запущен, а звука всё равно нет, учтите, что сессия по SSH не
имеет доступа к локальному звуковому серверу.

### `binaural: command not found` после установки

Симлинк лежит в `~/.local/bin`, а этот каталог не в вашем `PATH`. Добавьте:

```bash
# bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc

# zsh
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc && source ~/.zshrc
```

Проверьте через `ls -l ~/.local/bin/binaural` — если симлинка нет, перезапустите установщик с
`--prefix=DIR` и добавьте `binaural` в `PATH` напрямую.

### macOS: «невозможно открыть, потому что разработчик не проверен»

Приложение на Swift в `apple/` **не подписано**, поэтому Gatekeeper блокирует его любому, кроме
того, кто его собрал. Правый клик → *Открыть* в Finder и подтверждение в диалоге — это работает
один раз для конкретной сборки; либо снимите карантинный флаг из терминала:

```bash
xattr -d com.apple.quarantine /path/to/Binaural.app
```

На Apple Silicon System Settings → Privacy & Security тоже предлагает «Open Anyway» после первой
заблокированной попытки. Это относится к `apple/dist/Binaural.app`, а не к Python-версии:
установка из исходников собирается локально и через Gatekeeper не проходит.

### Биение не слышно на колонках

Так и должно быть, это не баг. На колонках две частоты смешиваются в воздухе до того, как достигнут
ушей, и эффект исчезает. См. [Почему наушники обязательны](#почему-наушники-обязательны).

## Участие в проекте

Работаете над этим репозиторием? Сначала прочитайте **[`CONTEXT.md`][context]** — там сказано,
где проект находится и что будет кусаться. Правила, обязательные для обеих реализаций, собраны в
**[`docs/CONTRACT.md`][contract]**; если реализация и спецификация расходятся, выигрывает
**[`docs/SPEC.md`][spec]**.

**Прогоняйте тесты перед коммитом.**

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest     # 488 успешно, 2 пропущено
```

У Swift своя серия тестов, и **в CI она не запускается** — каждый `xcodebuild` нужно выполнять
локально:

```bash
cd apple && xcodegen generate                               # 208 тестов core
xcodebuild -project Binaural.xcodeproj -scheme BinauralCore \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO test
xcodebuild -project Binaural.xcodeproj -scheme Binaural \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO test # + 141 тест окна
```

`CODE_SIGNING_ALLOWED=NO` здесь обязателен: сертификата Apple Developer нет.

Три соглашения, о которых стоит знать до первого коммита:

- **Идентификаторы и комментарии в коде — английские**; весь текст для пользователя идёт через
  `tr()` / `L10n.tr`. Русский каталог Swift *генерируется* из `src/binaural/locales/ru.py` — если
  менять один, перегенерируйте другой, иначе Swift-серия упадёт.
- **`frequencies.json` не дублируется нигде.** Это единственная копия справочника в репозитории, и
  Swift-серия намеренно фиксирует его счётчики: добавление записей означает правку JSON, литералов
  в Swift и `docs/FREQUENCIES.md` одним коммитом.
- **Коммит на пункт и никогда не заканчивайте незакоммиченной работой.** Проверяйте `git status`
  до и после.

Слои разделены намеренно: `core/` — чистая математика без импорта Qt (тестируется без
аудиоустройств), `audio/` — перечисление устройств и детект наушников, `ui/` — только
отображение. Общаются они через сигналы Qt.

## Планы

**v0.1.0 помечен и опубликован** — только исходники, к релизу не прикреплено ни одного
бинарника, потому что неподписанный `.app` распространять нельзя. В остальном это alpha.

**Сделано**

| Область | Состояние |
|---|---|
| Python core | стереоосциллятор с непрерывной фазой и плавными переходами, вывод через `QAudioSink`, состояние сессии, таймер воспроизведения, `difference_lock` — реализовано, есть тесты |
| Python audio | перечисление и классификация устройств (CoreAudio, `pactl`/`pw-cli`/`amixer`), эвристика наушников и перцептивный L/R-тест — реализовано, есть тесты |
| Python UI | главное окно с живым расчётом разности и несущей, реестр пресетов 7 категорий / 20 пресетов, диалог справочника, диалоги проверки наушников и L/R, Настройки, трей — реализовано, есть тесты |
| Тесты Python | **488 успешно**, 2 пропущено |
| `apple/` core | `BinauralCore` — равенство с Python доказывается тестом, а не только компиляцией |
| `apple/` macOS | живой звук, главное окно, полный реестр пресетов, справочник частот, проверка наушников, Настройки, О программе, таймер воспроизведения, пункт в строке меню, сохранение сессии, «Зафиксировать», EN/RU — реализовано, **208 тестов core + 141 тест macOS** |
| `apple/` Release | `apple/dist/Binaural.app`, **без подписи** |
| Упаковка для Linux | `install.sh`, спецификация PyInstaller и скрипт релиза на месте; **архив ещё не опубликован** |
| Windows | не начато |

**Дальше**

- **Релизные архивы для Linux** — упаковка на месте, но ничего не собрано и не прикреплено к
  релизу, поэтому `v0.1.0` — только исходники.
- **Windows** — WASAPI-бэкенд за `audio/platform/`, сборка PyInstaller, `install.ps1`
- Резервный вывод через `miniaudio` там, где недоступен `QAudioSink`
- **Скриншоты** — их пока нет, поэтому единственная картинка в этом файле — ASCII-схема из раздела
  [О проекте](#о-проекте)
- **iOS** — схема собирается и линкуется, но не запускалась ни разу: на этой машине нет runtime
  симулятора. `xcodebuild -downloadPlatform iOS` превращает это в настоящую проверку

**Честные ограничения**

- Приложение для macOS **не подписано** — на машине сборки нет identity Apple Developer, нет
  нотаризации и App Store. Gatekeeper заблокирует его любому, кроме сборщика.
- **Экспорта в WAV нет.** Сознательно отсутствует в обеих реализациях, спецификация считает его
  необязательным.
- Перцептивный L/R-тест и его краевые случаи может оценить только человек в наушниках.
